# Prompt for the external deep-research consultant

Read `LLM_DEEP_RESEARCH_HANDOFF.md` and `CONSULTANT_RESPONSE_CONTRACT.md` fully. Assume no repository, private chat, local dataset, build environment, runtime, Kaneo, Cerebro, or internal tools beyond what the handoff embeds.

Act as an independent political-theory, democratic-innovation, civic-technology, and research-methods consultant. Your task is not to agree with The Venus Project, its critics, or Mind Journal. Your task is to produce a current, source-backed synthesis that can safely drive an editorial correction.

## Primary objective

Using `synthesis / deep`, determine which current map entries, statuses, sources, glossary definitions, node boundaries, and two-axis placements should be retained, corrected, decomposed, removed, or held for verification. Reconstruct canonical technique families before proposing additions.

“Make sure all information is up to date” means:

- record access dates;
- distinguish active, maintained, deployed, dormant, historical, archived, and unverified;
- check current official sources against repositories, institutional evidence, independent reporting, and counterevidence;
- do not infer activity from HTTP 200;
- state unresolved conflicts rather than smoothing them over.

## Mandatory order

1. Restate exact decision, frozen baseline, constraints, and Definition of Done.
2. Classify every named anchor as `CANONICAL`, `PROJECT_LOCAL`, `SPECULATIVE`, `CONTRADICTED`, or `UNKNOWN`.
3. Reconstruct canonical political-spectrum, planning/market, expertise/participation, democracy-family, digital-governance, municipalist/social-ecology, and public-infrastructure models.
4. Audit ownership: person, organisation, tool, idea, source, implementation, and map node are different units.
5. Test hierarchy and scale one level above and below each mechanism.
6. Compose accepted facts before suggesting novelty.
7. Research the seven preliminary families adversarially; merge/split with evidence.
8. Audit all 26 current nodes and discover only decision-relevant omissions.
9. Apply a common placement rubric with uncertainty and decomposition tests.
10. Return the exact Markdown archive.

## Source discipline

- Use foundational/review sources for canonical definitions.
- Use official sources for self-description and current semantics.
- Use repositories/releases and dated institutional records for maintenance/deployment.
- Use primary empirical studies and independent evaluations for effectiveness.
- Seek strongest counterevidence and negative results.
- Treat Wikipedia as glossary/discovery support, not sole authority.
- Search relevant local languages when they plausibly expose unique evidence.

For every load-bearing source include title, author/publisher, publication date, URL, access date, exact claim, affected IDs, applicability, limitation, and counterevidence.

## Required decisions

For every current node return:

```text
KEEP | CORRECT | DECOMPOSE | REMOVE | VERIFY_FIRST
```

Include corrected type, role, scope, status, proposal, caveat, source set, coordinate/range, confidence, and exact reason. Do not assign a person’s entire ideology from one mechanism.

For proposed additions, show which family, evidence gap, regional blind spot, or maturity level they add. Include a null branch in which the current map is already broad enough.

Create the exact Markdown-only directory in `CONSULTANT_RESPONSE_CONTRACT.md`. Return extracted Markdown files by default. ZIP is optional only as a native attachment. Never return Base64 or raw archive bytes.
